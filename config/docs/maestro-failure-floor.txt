# The number of Maestro flows allowed to fail, per scope.
#
# This file is the measurement's floor: the debt the repository has accepted,
# written down where a diff can show it shrinking. The gate
# (`scripts/ci/check-maestro-results.py`) fails when a run fails MORE flows
# than the number here, and passes when it fails fewer — so the debt ratchets
# in one direction only, and an improvement never has to be argued for.
#
# The floor is data, not a constant in the gate's code, and nothing rewrites
# it: lowering it is a deliberate edit to this file, in the commit that says
# what was fixed. A floor a script regenerates is a floor that moves by
# itself, and the diff that shows the debt shrinking has to be somebody's
# decision.
#
# Format: one `<scope> <max-failing-flows>` per line. `#` starts a comment.
#
# The number is traceable to the flows: the gate names every flow that failed
# in a run (in the summary and in the JSON payload), so "full 30" is thirty
# flows a reader can go and look at, not an aggregate nobody can take apart.
#
# The debt's *shape* lives in the cause registry (config/docs/maestro-debt.yaml):
# a run that fails on a cause the registry does not list fails the gate, and a
# cause the registry marks as fixed that comes back is a regression. There is
# no hand-written list of failing flow names anywhere in the repository — the
# flows of a run are read from the run, and the registry that cannot rot is the
# cause registry, not a list of names somebody has to remember to update.
#
# Scopes:
#   full  — every flow in the catalogue (config/docs/maestro-flows.txt); the
#           nightly's four shards together.
#   smoke — the flows that declare the `smoke` tag; the suite a pull request
#           runs. The tag, not the directory: most smoke flows live outside
#           Maestro/flows/smoke/, and the runner filters on the tag.
#
# Measured 2026-10-22 by a full run of all 94 flows on the device
# (RMX3938, API 35): 64 passed, 30 failed, 7 of the failures in the smoke
# subset. The numbers below are that run's failure counts, so the gate passes
# today and fails the first time the debt grows.
#
# The smoke set has changed since that run — the floor is a count of failures,
# not a fraction of the suite — so a flow that joins the tag and fails is
# debt the floor does not know about until it is re-measured and the number
# below is raised deliberately.
#
# ── The tab -> menu migration: repaired, NOT yet re-measured ─────────────────
#
# Eighteen flows were in the 30 because they tapped a bottom-bar id the bar no
# longer draws (`nav_tab_plans`, `nav_tab_pomodoro`) or asserted a bar the app
# no longer has. They now reach their destination the way a person does — menu
# button, scroll the sheet, tap the entry — and the flows repaired in this
# change are:
#
#   Maestro/flows/plans/01..10               (ten flows, all tagged `plans`)
#   Maestro/flows/pomodoro/01..05            (five flows, all tagged `pomodoro`)
#   Maestro/flows/nav/01-tab-set.yaml        (tags `smoke`, `nav`; replaces the
#                                            deleted nav/01-no-calendar-tab.yaml,
#                                            so the smoke set holds one flow
#                                            where it held one before)
#   Maestro/flows/nav/bottom-nav-tabs.yaml   (tags `smoke`, `nav`)
#   Maestro/flows/smoke/01-launch-today.yaml (tag `smoke`; its copy of the
#                                            tab-set assertions moved to
#                                            nav/01-tab-set.yaml, which now owns
#                                            that contract)
#
# The numbers below are deliberately NOT lowered by this change. Parsing a flow
# is not running it: eighteen flows that have never been through a device are
# exactly the debt this header warns about, and a floor lowered by arithmetic
# would either go red on the next run for the wrong reason (18 failures against
# a floor of 12) or, worse, hide a real regression in those very flows under the
# slack that a wrong number leaves behind. So the floor stays at the one
# measurement it has — 2026-10-22 — and this change claims no re-measurement.
#
# The ratchet is applied by the commit that carries a run's result: that diff
# names the flows the run no longer fails, deletes each of them from the count,
# and lowers the number here by the count it lost — `full` by every repaired
# flow that passes, `smoke` by the `smoke`-tagged ones among them
# (nav/01-tab-set.yaml, nav/bottom-nav-tabs.yaml, smoke/01-launch-today.yaml are
# the three candidates, so `smoke` has at most three to give back). Until that
# run exists, a regression arriving in these flows still fails against the
# measured floor instead of against a number nobody took.

full 30
smoke 7
