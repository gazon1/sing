# The instrumented suite's floor: what an emulator run must deliver.
#
# Recorded from the instrumented suite; how many classes and tests it held is
# in the generated block at the end of this file, and that block is the only
# place the numbers live. A hand-written copy of them here was a second
# source of truth that lagged behind the first: the floor was rewritten to
# eight classes and twenty-six tests, and the sentence above still said
# seven and twenty-four.
# `scripts/check-instrumented-test-floor.py` holds every run to it.
#
# classes, tests — floors. A run with fewer of either means coverage was lost,
# and the run stays green because the report lists the tests that are left: a
# deleted class is a line in a diff nobody reads. The floor is the record of
# what the tier used to be.
#
# skipped — a ceiling, and it is 0. A skipped instrumented test says nothing
# about the app on a device, which is the only thing this tier knows, and a
# tier that reports "skipped" reads as a tier that ran. The ceiling is a policy
# value, not an observation: `--update-floor` carries it over instead of
# measuring it, because a writer that measured it would raise the ceiling every
# time a run skipped something — which is the one thing the ceiling exists to
# prevent.
#
# The floor ratchets in both directions, and that is the point of it. A run that
# delivers MORE than this file records is a finding too: the floor is behind the
# suite, and it then describes a tier that no longer exists. That is not
# hypothetical — the floor sat at five classes and nineteen tests while the
# suite had already grown to six and twenty-one, and the one-sided floor
# compared 21 against 19, found no drop, and stayed green. A floor that
# understates reality is not a weak floor; it is a floor that has stopped
# asking its question.
#
# Raising it is deliberate, because a floor that regenerates itself stops being
# a floor:
#
#   python3 scripts/check-instrumented-test-floor.py --update-floor
#
# rewrites the block below from the run on disk. It refuses a drop unless
# --allow-drop is passed (a drop means the tier lost coverage — investigate,
# do not regenerate), it refuses a run with skipped tests, it warns when the
# floor rises so that a filtered run is not recorded as the floor, and it
# leaves everything above the markers untouched.
#
# **The instrumented suite lost a class on purpose, and the floor says so.**
# `CreateTaskFlowTest` (three tests) asserted "create a task from the FAB" on the
# device. That scenario is owned by the desktop tier, whose flow test drives the same
# FAB and the editor that opens from it in seconds, so the device copy was a second
# assertion of a scenario that already had an owner. It was removed rather than kept
# deliberately: the device tier's remaining classes are the ones that observe
# something no other tier can (the real Keystore, the real Android shell), and this
# one did not.
#
# The loss is acknowledged here rather than regenerated silently: the tier is 8
# classes and 25 tests now. `CreateTaskFlowTest` is not back — the scenario it
# held is owned by the desktop tier — but the tier has one class it did not have
# before that removal: `TaskEditorDraftTest`. One of its two tests owns what only
# a device can observe — an editor restoring a draft that outlived the process —
# and the other holds the harness helper to its boundary: the editor's drafts are
# cleared and the `DataStore` the app's settings share is not emptied.
# `--update-floor --allow-drop` is the documented override for a deliberate
# deletion; without it the tool refuses a drop, which is the point.
#
# GENERATED:BEGIN — rewritten by --update-floor; do not hand-edit
classes 8
tests 25
skipped 0
# GENERATED:END
