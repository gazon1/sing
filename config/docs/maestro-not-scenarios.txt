# Maestro flows that are deliberately NOT scenarios.
#
# `just trace-maestro-suggest` proposes a scenario tag for every flow that does
# not carry one. Reading a flow and deciding "this is navigation, not a user
# story" is a real decision — but without a way to record it, the decision is
# lost the moment the command is closed, and the same flow comes back next month
# as if nobody had ever looked at it. That is what makes the worklist permanent:
# it is not a backlog of unknown work, it is a backlog of unread work.
#
# Format — one flow per line, `#` starts a comment, blank lines ignored:
#
#     <path relative to the repo root>  —  <why this is not a scenario>
#
# The reason is mandatory. An entry with no reason reads as "someone decided
# something once" and gets deleted in a cleanup pass by the next person who
# wonders why the file exists; a reason is a claim that can be disagreed with.
#
# What belongs here
# -----------------
# Flows that exercise the shell rather than a feature: navigation, smoke, and
# the empty-state passes that assert a screen renders rather than what it does.
#
# What does NOT belong here
# -------------------------
# A flow that tests real behaviour and has no scenario spec yet. That is a gap,
# and it is listed by `just trace-maestro-suggest` until somebody writes the
# spec. Putting it here would convert "we have not written this down" into "we
# decided not to", which is the opposite truth and is invisible afterwards.
#
# Adding an entry is a deliberate act; removing one re-opens the question.
