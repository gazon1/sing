# The gate catalogue

The shape of the gate suite: the modules it is built from, the helper tools around it, and the scripts that no gate runs. The gates themselves are described once, in `docs/scripts/gate-registry.md` — that document says what each gate is called, whether it stops the build, and what it checks. Generated by `python3 scripts/check-tools-catalog.py --write` — do not edit it by hand; the check `--check` fails when it is stale.

## Scripts outside the gate registry

A gate script that no registry entry names is not a gate — it is run by a surface that is not the registry: a step of the CI workflow, or the preamble of the static job. They are listed here so that the difference between a gate and a helper is visible rather than assumed.

| Script | What it is |
|---|---|
| `scripts/check-gate-tooling-origin.py` | check-gate-tooling-origin.py — the gate CLI must serve THIS checkout. |
| `scripts/check-gate-wiring.py` | check-gate-wiring.py — prove the gates exist AND that they can fail. |
| `scripts/check-openspec-stale.py` | Warn when an active OpenSpec change is older than 14 days. |
| `scripts/check-slow-tests-ran.py` | check-slow-tests-ran.py — every `@Tag("slow")` class ran in the full suite. |

## The rest of the surface

| Tool | What it is |
|---|---|
| `scripts/ci/static-gates.sh` | The registry of the gates that need no JVM; `sgate run-all` reads it. |
| `scripts/ci/setup-local-tools.sh` | Installs the gate suite into a uv venv — the local package, editable. |
| `scripts/ci/preflight-gate-tools.sh` | Says which tool is missing and how to get it, before a gate cannot run. |
| `scripts/ci/new-gate.py` | Registers a gate in every place it has to be, in one command. |
| `scripts/detekt-summary.py` | Prints the detekt findings by rule and by place, instead of XML per finding. |
| `scripts/ci-verdict.py` | Prints the CI verdict of a commit, a branch or a pull request: the workflow, the run, the conclusion. |
