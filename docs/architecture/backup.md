# Бэкап: форма пакета `core/backup`

> **Reference, not a procedure.** Что лежит в пакете и где: виды строк и порядок их
> удаления, части архива, DTO по доменам, кто что проверяет. Решения — в ADR; этот
> файл отвечает на «где что лежит», а не «почему так».

## Виды строк и порядок удаления

`BackupEntityKind` (`BackupEntityKind.kt`) — вид строки, под которым ищется её ключ:
индекс экспорта это карта «вид → строки этого вида», и строка — «та же строка», когда
у неё тот же ключ **внутри своего вида**. Задача и заметка могут делить id и при этом
быть разными строками.

Каждый вид объявляет фазу, в которой он удаляется (`BackupRemovalPhase`), и фаза —
аргумент конструктора, а не значение по умолчанию: вид, добавленный без фазы, не
компилируется. Виды объявлены в том порядке, в котором удаляются, поэтому весь
порядок — один список в одном месте, а импортёр читает его, а не читатель считает
строки.

Фазы идут так: сначала дети (ссылки и строки, висящие на родителе), потом сами
строки, потом родители — и последними. Таблицы ссылок не имеют своего `user_id`:
строка `task_tags` принадлежит владельцу задачи, и удаляет её запрос, который
доходит до своей строки через задачу. Обратный порядок оставил бы ссылку рядом с
задачей, которая уже не нужна, — а каскада у этих таблиц нет.

Запись об этом: `docs/decisions/2026-10-27-the-removal-order-is-a-declaration.md`.

## Части архива

| Файл | Что в нём |
|---|---|
| `ArchiveFormat.kt` | числа, из которых собраны байты: версии, соль, nonce, пределы цепочки |
| `ArchiveBytes.kt` | арифметика контейнера: целые числа big-endian, туда и обратно |
| `ArchiveFrame.kt` | кадр изменения: длина, nonce, тело |
| `ArchiveHead.kt` | голова цепочки: сколько изменений и сколько байт |
| `ArchiveContainer.kt` | контейнер: версия, соль, nonce, голова, блок ключа |
| `ArchiveChainReader.kt` | чтение изменений цепочки |
| `ArchiveChainOpener.kt` | чтение контейнера: сначала отказ по счётчику, потом сессия |
| `ArchiveChainWriter.kt` | запись цепочки: кадры, голова, заголовок, база |
| `ArchiveChainLimit.kt` | предел, в который цепочка должна поместиться |
| `ArchiveCryptoSession.kt` | ключ и вызовы шифра |
| `ArchiveEnvelopeError.kt` | семейства ошибок архива |
| `ArchiveErrorMapping.kt` | что означает та или иная ошибка |
| `ArchiveSealer.kt` | чем запечатывается архив: паролем или ключом устройства |
| `EncryptedArchive.kt` | форма: что архив запечатывает и что открывает |

Счётчик в голове читается **до** того, как доказан пароль, поэтому отвергается
раньше, чем может стать циклом, выделяющим память. Строка, которая это делает,
названа в тесте-сканере исходников
`shared/src/jvmTest/kotlin/com/singularity/todo/arch/BackupChainGuardTest.kt`.

## DTO по доменам

`BackupDtos.kt` был одним файлом на 815 строк и 36 функций — больше, чем допускает
detekt (25 на файл). Теперь по домену:

| Файл | Строки |
|---|---|
| `BackupTaskDtos.kt` | задача и то, что висит на ней: теги, зависимости, чек-лист, напоминания, записи времени |
| `BackupNoteDtos.kt` | заметки |
| `BackupProjectDtos.kt` | проект, его напоминания и унаследованные группы тегов |
| `BackupTagDtos.kt` | теги и группы |
| `BackupAttachmentDtos.kt` | вложения и аннотации к ним |
| `BackupSavedViewDtos.kt` | сохранённые представления и поиски |
| `BackupProfileDtos.kt` | профили |
| `BackupLinkList.kt` | два помощника: список ссылок в текстовой колонке |

## Кто что проверяет

| Проверка | Где |
|---|---|
| у каждого вида есть путь удаления | `shared/src/jvmTest/kotlin/com/singularity/todo/arch/BackupRemovalPathTest.kt` |
| порядок удаления — тот, что объявлен | `shared/src/jvmTest/kotlin/com/singularity/todo/arch/BackupRemovalPathTest.kt` |
| сторож счётчика на месте | `shared/src/jvmTest/kotlin/com/singularity/todo/arch/BackupChainGuardTest.kt` |
| путь удаления удаляет свою строку из своей таблицы | `shared/src/jvmTest/kotlin/com/singularity/todo/core/backup/BackupRemovalPathTest.kt` |
| цепочка идёт от экспорта до восстановления | `shared/src/jvmTest/kotlin/com/singularity/todo/core/backup/BackupChainTest.kt` |
| бэкап переживает круг: экспорт и восстановление | `shared/src/jvmTest/kotlin/com/singularity/todo/feature/backup/BackupRoundTripTest.kt` |

Первые две проверки читают исходники: они говорят, что путь есть и что порядок
объявлен. Последняя из таблицы — единственная, которая говорит, что путь удаляет
**свою** строку из **своей** таблицы: остальные не узнают, в какую таблицу смотрит
ветка.
