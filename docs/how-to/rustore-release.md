# Публикация в RuStore — первая версия и последующие релизы

Операционная процедура для магазина RuStore: что загружать, чем заполнять карточку,
кто и что делает вручную, что делает API, и какие идентификаторы нужны CI.

Состояние на 2026-11-16: приложение создано, первая активная версия **не опубликована**.

## 3. Почему первую версию загружают руками

RuStore Public API не умеет создавать черновик первой версии: сервер требует, чтобы у
приложения уже была хотя бы одна активная версия. Проверено:

```
POST /public/v1/application/com.singularity.todo/version  → 403
  {"code":"ERROR","message":"This user does not have rights to perform this action."}
GET  /public/v1/application/2063789931/version             → 403 (тот же ответ)
```

Два разных ответа на два разных вопроса:

- `403 … does not have rights` — у ключа API нет в scope нужных методов («создание
  версии», «загрузка APK», «отправка на модерацию») **или** нет доступа к этому
  приложению. Причина выбирается на стороне Console при генерации ключа: выбрать
  приложение `com.singularity.todo` и нужные методы.
- Первая активная версия в любом случае создаётся в Console — API для этого не
  приспособлен.

Итог: **bootstrap делает человек в RuStore Console**, API используется для чтения
состояния и для последующих публикаций (#3000).

## 4. Авторизация в API

Хост: `https://public-api.rustore.ru`. (`public-api-m.rustore.ru` из этой сети
недоступен — TLS-ошибка.)

1. Подпись: `timestamp` = текущее время UTC в ISO-8601 с миллисекундами
   (`datetime.now(timezone.utc).isoformat(timespec="milliseconds")`), подпись =
   base64 от `SHA512withRSA(keyId + timestamp)`.
2. `POST /public/auth/` с телом `{"keyId","timestamp","signature"}` → `body.jwe`.
3. Токен живёт 900 секунд; каждый запрос — с заголовком `Public-Token: <jwe>`.

```bash
JWE=$(python3 /tmp/rsauth.py 2351035476 | python3 -c 'import json,sys; print(json.load(sys.stdin)["body"]["jwe"])')
curl -s -H "Public-Token: $JWE" https://public-api.rustore.ru/public/v1/application
```

Секрет (`RUSTORE_KEY`) лежит в `~/.zshrc` и **никогда** не попадает в репозиторий,
логи или CI-лог. В CI (#3001) — только GitHub Actions secrets.

## 5. Что делает человек в RuStore Console (bootstrap первой версии)

Порядок (по документации RuStore): черновик версии → APK → иконка и скриншоты →
заполнение карточки → отправка на модерацию → публикация.

1. **Черновик версии**: версия `0.2.1`, versionCode `2001` (RuStore требует, чтобы
   versionCode новой версии был строго больше предыдущего).
2. **APK**: `singularity-0.2.1-android.apk` из п. 2 (подписан тем же ключом, что и
   остальные релизы; fingerprint сверяется с `vars.ANDROID_CERT_FINGERPRINT`).
3. **Иконка**: PNG 512×512 — `scripts/render-rustore-icon.py` (см. п. 6).
4. **Скриншоты**: минимум 3, до 10; PNG/JPG, до 3 МБ каждый, не выше 2160×3840,
   соотношение 16:9 (см. п. 6).
5. **Карточка**: тексты из п. 7 — копируются как есть.
6. **Модерация**: отправка на модерацию; после одобрения — публикация.
   Публикация — действие человека, API её не делает за него.
7. **Зафиксировать**: после публикации — `appId` (уже известен: `2063789931`) и
   активный `versionCode` — их и ждёт #3001.

## 6. Иконка и скриншоты

### Иконка 512×512

В репозитории максимум — растр 192×192 и два вектора адаптивной иконки
(`drawable/ic_launcher_background.xml`, `drawable-v24/ic_launcher_foreground.xml`).
Скрипт рендерит их в PNG 512×512 (видимая область адаптивной иконки — 72 из 108 dp):

```bash
pip install cairosvg
python3 scripts/render-rustore-icon.py --out build/rustore/icon-512.png
```

### Скриншоты

Снимаются с эмулятора/устройства, где установлен **тот же** APK, что уходит в
магазин, и показывают состояние с демонстрационными данными (реальные пользовательские
данные в публичных скриншотах недопустимы).

Требования RuStore: 1–10 скриншотов мобильной версии, PNG/JPG, до 3 МБ, до
2160×3840, 16:9.

Рецепт (эмулятор, 16:9, демо-данные):

```bash
# 1. Экран 16:9 — RuStore просит именно такое соотношение.
adb shell wm size 1080x1920

# 2. Демо-данные: deep-link сидер из debug-сборки (todo-debug://seed?task=…&due=today).
#    Он живёт только в debug-варианте: в release APK его нет.

# 3. Снимок.
adb exec-out screencap -p > shot-01-agenda.png
```

Подходящие экраны: повестка дня, карточка задачи, заметки, календарь, список
предстоящего.

Оговорка по языку: локализация в приложении частичная — ресурсные строки русские, а
нижнее меню и часть подписей («Good evening», «Today», «Add task», «No priority»)
захардкожены по-английски. Даты, кстати, всегда русские (`RussianDateFormatter`).
Поэтому скриншоты сняты в русской локоли, а английские подписи на них — реальный вид
приложения, а не ошибка съёмки.

## 8. Известные ограничения текущего релиза

- **APK `v0.2.1` собран без `supabase.url` / `supabase.anonKey`** (release.yml
  инжектит только `google.client.id`). Поэтому первый запуск у пользователя магазина
  показывает экран «Connect your server», и продолжить можно только введя URL и
  anon key своего Supabase-проекта. Кнопки «Continue without an account» в этой
  сборке ещё нет — она появилась в коде позже (`LoginScreen.kt`,
  `AUTH_CONTINUE_OFFLINE_BUTTON`).
  До публикации это стоит исправить: либо релиз с зашитым URL/ключом проекта, либо
  сборка с офлайн-стартом по умолчанию. Это отдельная задача, не эта.
- Скриншоты для карточки сняты с debug-сборки из текущего `main` (в ней офлайн-режим
  и демо-данные есть), потому что релизный `v0.2.1` дальше экрана подключения к
  серверу не идёт.
- Локализация частичная: подписи нижнего меню и части экранов захардкожены
  по-английски, даты — всегда по-русски. Это видно на скриншотах и это реальный вид
  приложения.
