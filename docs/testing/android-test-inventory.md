## Disposition legend

| Disposition | Meaning |
|---|---|
| `keep` | Keep in current tier. The scenario or platform guarantee has no equivalent faster owner. |
| `replace` | A faster tier already owns the equivalent scenario/guarantee; this copy can be removed by a follow-up change issue. |
| `merge` | Coverage should be consolidated with an existing test in the same or another tier; follow-up should preserve all guarantees. |
| `investigate` | Overlap or ownership is plausible but not proven equivalent, or execution/wiring makes ownership unclear. |

## Cross-cutting findings

- **Complete enumeration:** All 22 Kotlin files under `androidApp/src/androidTest` and 9 under `shared/src/androidHostTest` are listed above. The counts are reproducible with the commands in "Reproducible scope".
- **No changes made:** No tests, production code, Gradle config, floors, baselines, or CI lanes were modified by this audit.
- **Known example validated:** `NotificationPermissionRequesterComposeTest` (device) and `NotificationPermissionRequesterTest` (androidHostTest) are not interchangeable. The host test proves LifecycleRegistry observer behavior/registration; the device test proves production Compose `DisposableEffect` wiring, lifecycle-owner swap, and disposal through the mounted composable. `NotificationSupportTest` (JVM) separately owns the permission rule matrix.
- **ScreenInspector coverage:** `shared/src/jvmTest/kotlin/com/singularity/todo/mcp/introspection/ScreenInspectorRuntimeTest.kt` and `ScreenInspectorHostContractTest.kt` exist and own JVM/headless runtime and host request-boundary behavior, as the issue states. No Android/androidHostTest ScreenInspector tests were found in scope.
- **Execution wiring gap:** `AndroidFileSourceTest.kt` exists in `shared/src/androidHostTest` but is not included in `shared/build.gradle.kts` `testAndroidHostTest.include(...)`. Its 3 tests are not part of the executed 23-test baseline. Disposition is `investigate` because behavior is platform-relevant but currently unwired.
- **Duplicate-coverage candidate for follow-up (not changed here):** `androidApp/.../ui/CreateTaskFlowTest.kt` overlaps desktop `CreateTaskFlowTest` and Maestro `tasks/create-task.yaml`, but disposition is `investigate` until remaining Android shell/editor/resource-id wiring has explicit owners.
