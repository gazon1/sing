# Политика конфиденциальности — Singularity Todo

**Приложение:** Singularity Todo (`com.singularity.todo`)
**Версия документа:** 1.1 (актуально для версий 0.2.x)
**Разработчик:** Дробин Максим
**Контакт:** [newbox2517@inbox.ru](mailto:newbox2517@inbox.ru)
**Исходный код:** [https://github.com/gazon1/sing](https://github.com/gazon1/sing)

> English summary: this app stores your tasks, notes, projects and reminders locally on
> the device. The build you install does not bundle a backend of ours: if you want sync,
> you connect your own Supabase project by entering its URL and publishable anon key, and
> your data is then stored there under your account, on a server you control. If you use
> AI features, the text you ask the assistant to process is sent to the LLM provider you
> configured yourself. There is no analytics, advertising or crash-reporting service in
> this build. Everything else stays on the device.

## 1. Какие данные обрабатывает приложение

| Категория             | Что именно                                                                                     | Где хранится                                                                    |
| --------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Задачи                | Заголовок, описание, статус, приоритет, сроки, повторение, чек-листы, зависимости, напоминания | Локально (база Room) и, при включённой синхронизации, на подключённом сервере    |
| Заметки               | Текст заметки (в т.ч. форматирование), вложения                                                | Локально; на подключённый сервер — при включённой синхронизации                  |
| Проекты и теги        | Название, цвет, иконка, счётчики                                                               | Локально; на подключённом сервере — при включённой синхронизации                 |
| Вложения (файлы)      | Содержимое прикреплённых файлов                                                                | Только на устройстве, в приватном каталоге приложения; на сервер не выгружаются |
| Черновики             | Незавершённые тексты полей ввода                                                               | Только на устройстве                                                            |
| Учётная запись        | Адрес электронной почты, пароль (только хеш на стороне сервера)                                | На подключённом сервере (Supabase Auth)                                         |
| Профиль синхронизации | Имя профиля, эмодзи, цвет                                                                      | На подключённом сервере                                                          |
| Календарь             | События календаря Google, выбранные для синхронизации                                          | Локально и в Google Calendar; refresh-токен Google — на подключённом сервере     |
| Ключи                 | API-ключ ИИ, ключ шифрования резервной копии, OAuth-токены Google                              | Только на устройстве, в защищённом хранилище ОС (Android Keystore)              |
| Служебное             | Идентификатор устройства, журнал использования ИИ, кэш удалённой конфигурации                  | Только на устройстве                                                            |

Приложение **не собирает** геолокацию, контакты, историю звонков, идентификаторы рекламных
сетей, данные о здоровье, платежах и «пересечении» с другими приложениями.

## 2. Куда данные уходят

### 2.1. Подключённый сервер (необязателен)

Магазинная сборка **не содержит** сервера разработчика: URL и anon-ключ проекта в неё не
зашиты. Если вы хотите синхронизацию, вы сами указываете на первом экране адрес своего
проекта Supabase и его публичный (publishable) anon-ключ — это публичный идентификатор,
он предназначен для чтения и не является секретом. Эти два значения сохраняются в
защищённом хранилище на устройстве и передаются только по указанному вами адресу.
Разработчик их не получает и не видит.

Если сервер не подключён, приложение работает полностью локально: задачи, заметки,
проекты, напоминания и таймеры остаются на устройстве, и ничего никуда не отправляется.
Пункт «Продолжить без учётной записи» на первом экране делает именно это.

### 2.2. Синхронизация (необязательна)

Синхронизация включается вами явно. После включения содержимое задач, заметок, проектов
и тегов передаётся на подключённый вами сервер (Supabase) и хранится в базе данных под
вашей учётной записью. Доступ к этим строкам ограничен правилами безопасности на уровне
строк (RLS): прочитать или изменить их может только владелец записи. Разрешение
конфликтов — по логике HLC (hybrid logical clock).

### 2.3. Резервные копии

Экспорт создаётся на устройстве, шифруется **на устройстве** (AES-GCM, ключ из
PBKDF2, либо ключ устройства из системного хранилища) и загружается в приватное
хранилище `backups` на подключённом вами сервере. Файл бэкапа не читается без пароля/ключа.
Имя объекта хранилища не шифруется. Резервную копию можно удалить из приложения (см. §5).

### 2.4. ИИ-функции (необязательны)

Провайдер и ключ задаёте вы сами (OpenAI, любой OpenAI-совместимый или
Anthropic-совместимый endpoint, Ollama). При использовании ИИ-функций текст задач
и заметок, который вы передали помощнику, уходит **выбранному вами провайдеру**.
Данные не передаются в ИИ, если вы не вызывали ИИ-функцию. Локальный режим
(Ollama на `localhost:11434`) не покидает устройство вовсе.

### 2.5. Календарь Google

По вашему явному запросу приложение получает доступ к календарю Google
(scope `https://www.googleapis.com/auth/calendar`, PKCE) и читает/создаёт/удаляет
события. Refresh-токен Google хранится в таблице `public.google_calendar_grants`
на подключённом вами сервере, под вашей учётной записью. Отзыв доступа выполняется в
настройках Google.

### 2.6. Обновление приложения

Проверка новых версий выполняется через тот канал, который задан для этой сборки:
Google Play In-App Update (системный компонент Android) или карточка приложения в
RuStore — в RuStore-сборке приложение открывает страницу приложения в магазине.
Трекеры и рекламные SDK отсутствуют.

## 3. Разрешения ОС и зачем они нужны

| Разрешение                                                                                                        | Назначение                                                                               |
| ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `INTERNET`, `ACCESS_NETWORK_STATE`                                                                                | Синхронизация, резервные копии, ИИ, проверка обновлений                                  |
| `POST_NOTIFICATIONS`                                                                                              | Уведомления о наступлении сроков и напоминаний                                           |
| `RECEIVE_BOOT_COMPLETED`, `WAKE_LOCK`, `USE_EXACT_ALARM`, `SCHEDULE_EXACT_ALARM`, `VIBRATE`, `FOREGROUND_SERVICE` | Локальные напоминания работают и после перезагрузки                                      |
| `READ_CALENDAR`, `WRITE_CALENDAR`                                                                                 | Двусторонняя синхронизация с календарём Google                                           |
| `READ_MEDIA_IMAGES`, `READ_EXTERNAL_STORAGE` (≤ API 32)                                                           | Выбор изображения для вложения к задаче (в текущей версии объявлено, но не используется) |
| `USE_BIOMETRIC`, `USE_FINGERPRINT`                                                                                | Объявлены транзитивно библиотекой хранилища; вход по биометрии в приложении не используется |

## 4. Аналитика и crash-reporting

В опубликованной сборке **нет** аналитики, рекламных SDK и внешнего сброса
crash-отчётов: счётчики аналитики отключены, отчёты об ошибках пишутся в локальный
файл журнала на устройстве и не покидают его.

## 5. Хранение и удаление

- Данные в приложении живут, пока установлено приложение; удаление приложения удаляет
  локальную базу, вложения и ключи.
- **Удаления учётной записи в приложении нет.** Синхронизированные записи, профиль
  синхронизации и резервные копии остаются на подключённом вами сервере, пока вы сами их
  не удалите. Сделать это можно в консоли Supabase (раздел Authentication → Users):
  удаление пользователя удаляет и его синхронизированные записи — в схеме базы у них
  стоит `on delete cascade`. Файлы резервных копий удалите отдельно, в разделе Storage
  → бакет `backups`, либо из приложения (см. следующий пункт).
- Резервные копии удаляются из приложения: раздел «Резервные копии» → кнопка Delete →
  подтверждение. Срок их хранения сервером не ограничен отдельно.
- Журналы ошибок на устройстве удаляются вместе с приложением.

## 6. Передача третьим лицам

Мы не продаём и не передаём ваши данные третьим лицам. Данные могут обрабатывать
только: хостинг подключённого вами сервера (Supabase), Google (календарь — по вашему
запросу) и выбранный вами провайдер ИИ. Все три получают ровно тот объём данных, который
нужен для соответствующей функции.

## 7. Дети

Приложение не предназначено для детей и не содержит проверки возраста: ответственный
взрослый должен контролировать использование. Возрастная категория в карточке магазина —
«0+», то есть ограничения по возрасту в магазине не заявлены.

## 8. Изменения

Политика меняется по мере появления новых функций; дата и версия документа — в
начале файла. Предыдущие версии доступны в истории репозитория.
