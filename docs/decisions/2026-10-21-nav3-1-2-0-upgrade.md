# Navigation 3 moves to 1.2.0 and the deep-link API arrives with it

## Context

The app ran on `androidx.navigation3` 1.1.1. Two things were missing there:

1. **No deep-link API.** The package `androidx.navigation3.runtime.deeplink` does not exist in
   1.1.1 — `DeepLinkRequest`, `UriDeepLinkMatcher`, `DeepLinkUri` all arrive in 1.2.0, in
   `commonMain`. The app therefore hand-parsed every incoming URI: `MainActivity` matched
   `data.scheme == "singularity" && data.host == "task"` by hand, read the magic-link parameters
   from *any* intent data without checking scheme or host, and kept the four results as four
   `String?` parameters on `App(...)`.
2. **Dead weight in the dependency graph.** `io.insert-koin:koin-compose-navigation3` 4.2.2 was
   declared but never imported anywhere; it is built against `navigation3-runtime:1.0.1` and had
   to be carried in `scripts/dependency-usage-allowlist.txt`.

The JetBrains multiplatform UI artifact (`org.jetbrains.androidx.navigation3:navigation3-ui-desktop`)
is released separately from the androidx line and lags it: at the time of writing the newest
version on Central is `1.2.0-rc01`, whose module metadata requires
`androidx.navigation3:navigation3-runtime:1.2.0`. The two artifacts are therefore compatible.

## Idea

Move the runtime and the Android UI to 1.2.0, move the JetBrains UI to 1.2.0-rc01, and drop
the unused Koin artifact. Take the deep-link API from the runtime as the foundation for the
registry that PR-2 builds.

## Decision

- `nav3 = "1.2.0"` for `androidx.navigation3` (runtime, runtime-android, runtime-desktop,
  ui-android) and a **separate** `nav3-ui-desktop = "1.2.0-rc01"` for the JetBrains UI artifact.
  The two refs must not be merged: the JetBrains line has no `1.2.0` final.
- `koin-compose-navigation3` (and its `-android` alias) are deleted from the version catalog and
  from `shared/build.gradle.kts`; the entry in `scripts/dependency-usage-allowlist.txt` is removed.
  The allowlist ceiling stays at 11 — the gate is a floor on *allowed* dependencies, and removing
  one only makes the graph stricter.
- `NavDisplay` calls keep the parameters they have. The 1.2.0 UI artifact declares the
  single-`sceneStrategy` overloads with `DeprecationLevel.HIDDEN`, so they are invisible to the
  compiler and every call resolves to the `sceneStrategies: List<SceneStrategy<T>>` overload,
  whose default is `listOf(SinglePaneSceneStrategy())` — the same single-pane behaviour as before.
  No call site needs an explicit `sceneStrategies` argument.

## Rationale

- **Hidden, not deprecated.** `DeprecationLevel.HIDDEN` removes the overload from overload
  resolution entirely; a call that would have matched only the old overload becomes a compile
  error, not a warning. The compile of all three source sets is the proof that no such call
  survived.
- **One behaviour, two artifact lines.** The androidx artifacts and the JetBrains artifact are
  published on different schedules. Pinning the JetBrains line to its own ref keeps the pair
  explicit instead of hiding a downgrade inside a resolution strategy.
- **Deleting the unused artifact removes a constraint.** `koin-compose-navigation3` 4.2.2 is
  compiled against nav3 1.0.1; on the classpath next to nav3 1.2.0 it is a stale duplicate of
  the runtime that nobody calls.

## Consequences

- **Always** pin the JetBrains nav3 UI to the newest version that actually exists on Central;
  never assume the androidx line and the JetBrains line release together.
- **Never** re-add `koin-compose-navigation3` unless the `navigation { }` DSL is actually used.
  The app builds its entry providers with `androidx.navigation3.runtime.entryProvider { }`.
- **Always** expect `NavDisplay`'s single-`sceneStrategy` overloads to be gone on the next
  upgrade; the `sceneStrategies` list is the replacement.
- **`defaultContentKey` changed in 1.2.0**: it was `key.toString()` and is now `"$key:${key::class}"`.
  The content key therefore differs across the upgrade, so **saved navigation state does not
  survive an app update**. This is accepted: the state that would have been restored is a
  back stack, and losing it means the app opens on its start tab instead of on a half-restored
  deep stack. No migration is written for it.
- `androidx.navigationevent:navigationevent-compose` enters the dependency graph transitively
  (1.1.1 on Android, 1.1.0 on Desktop through the JetBrains artifact).
