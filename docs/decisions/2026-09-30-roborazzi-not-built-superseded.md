# Roborazzi snapshot tests — не реализовано, решение закрыто

## Context

ADR `2026-09-08-roboazzi-snapshot-tests` (`status: accepted`) предлагал внедрить
Roborazzi для снапшот-тестов восьми компонентов экрана задачи и объявил
CI-гейт: «`./gradlew :shared:verifyRoborazzi` must pass».

Ни одно из этих утверждений не соответствовало репозиторию. Проверено прямо,
а не по памяти:

| Утверждение ADR | Реальность |
|---|---|
| «Integrate Roborazzi in `shared/build.gradle.kts` via plugin» | Плагина нет; `grep -ri roborazzi --include=build.gradle.kts` пуст по всему репозиторию |
| «`./gradlew :shared:verifyRoborazzi` must pass» | Задачи не существует: `./gradlew :shared:tasks --all` не находит ни одной задачи с `roborazzi` |
| «Baseline images stored in `shared/src/commonTest/resources/roborazzi/`» | Каталога нет |
| Снапшоты для 8 компонентов | Из восьми имён в `shared/src` встречается только `AttachmentThumbnail` (2 ссылки). `TaskHeroSection`, `TaskMetaChipsRow`, `TaskChecklistSection`, `TaskBottomActionBar`, `SubtaskRow`, `ReminderListRow`, `PickerSheetHost` — ноль ссылок: рефакторинг задачного экрана, на который ссылался ADR, был переписан |
| Версия в каталоге | `roborazzi = "1.74.0"` и `io.github.takahirom.roborazzi:roborazzi` объявлены в `libs.versions.toml` и **не используются ни одним build-файлом** |

Реализации было 0%. Статус при этом оставался `accepted`, а в
`libs.versions.toml` висела запись, которая выглядела как рабочая зависимость.
Это ровно тот класс дефекта, что план помечает «C. Объявлено, не действует»:
запись в каталоге версий читается как «мы это используем».

Два факта усиливают вывод, и оба обнаружены при этой же проверке:

- ADR `2026-09-18-version-catalog-cleanup` **уже перечислил** `roborazzi` среди
  мёртвых записей каталога («never used») — и запись всё равно осталась на
  месте. Долг был не незамеченным, а задекларированным и не закрытым: запись в
  ADR очистки не превращается в действие без гейта.
- Скилл `singularity-todo-task-snapshot-testing` (169 строк) учит настраивать
  Roborazzi: координаты, плагин, API захвата, CI. Целый скилл об инструменте,
  которого в проекте нет, — и его `description` не даёт понять это до чтения.

## Idea

Вариантов было три: реализовать снапшоты сейчас, оставить ADR в `accepted` и
надеяться, что кто-то дойдёт, или честно закрыть решение.

## Decision

**Суперсидить ADR `2026-09-08`, удалить неиспользуемые записи из
`libs.versions.toml`, пометить скилл непринятым и сошласовать запись R30 в
`2026-09-26-deferred-r25-r30`.**

Ничего не реализовывать сейчас: снимки экрана — не то, что чинит текущие
проблемы, а цена входа (сгенерированные baseline-картинки, отдельная задача
верификации, решение о tolerance и о том, что делать с ними на Android) высока
по сравнению с пользой, которую даёт детерминированный слой Compose-тестов,
который уже есть.

Удаление из `libs.versions.toml` — не косметика. Неиспользуемая запись каталога
это ловушка: она отвечает на вопрос «мы используем Roborazzi?» утвердительно и
уводит читателя в сторону.

## Rationale

- Ложный ADR хуже отсутствующего. `accepted` на нереализованном решении
  заставляет следующего читателя искать код, которого нет, — это ровно та
  потеря времени, которую эта работа и пытается устранить.
- Версия `1.74.0` в каталоге ни к чему не привязана; оставлять её — значит
  оставлять зависимость, которую придётся разбирать при первом же обновлении.
- Paparazzi как альтернатива из старого ADR не рассматривается: он Android-only,
  а проект — Android + JVM Desktop, то есть он закрывает половину платформ.
- Скилл не удалён, а помечен: 169 строк наработок — это дешёвая заготовка на день,
  когда тема вернётся, а удаление уничтожило бы единственную запись найденных
  координат. Но его `description` теперь должен говорить «не принято», иначе
  агент, ищущий скилл по описанию, получит инструкцию для несуществующего
  инструмента.

## Consequences

- Триггер возврата: снапшоты понадобятся, когда детерминированные
  Compose-тесты перестанут покрывать регрессии — то есть когда появится
  визуальная регрессия, которую ассертами не поймать. До этого решение не
  висит в бэклоге.
- Если вернуться к теме: Roborazzi нужно брать в **стабильной** версии, не в
  alpha, и сначала доказать на JVM Desktop, что он вообще работает с Compose
  Multiplatform 1.12. Старый ADR это не проверял.
- Проверка «запись каталога используется» в `docs/build-lint` (пункт C плана)
  ловила бы это автоматически. Закрыт вручную; автоматическая проверка не
  добавлена и остаётся отдельной задачей.
