# PR 2.4a/2.4b Re-scoped

The roadmap planned sub-ViewModel extraction for both god-VMs. Reading the
actual code (post-MR-6d) changed the right move for both.

## PR 2.4a — SettingsViewModel: boilerplate collapse, NOT sub-VM split

The planned split (Notifications/Ai/Backup/About sub-VMs) was rejected:

- The sections are **already decoupled** — the Contributor pattern
  (`SettingsContributor<S, I>`) gives each area its own state source and
  processor. The VM is a coordinator, not a god.
- The 347 lines were **mechanical duplication**, not coupling: 6 near-identical
  dispatchers (`clear error → fireAndForget → contributor.process`) and 7
  identical observe-collect blocks.
- Sub-VMs would move the merge problem to the screen (4 `koinViewModel()`s +
  a new aggregation layer) without removing anything.

**Done instead (347 → 182 lines, zero behavior change):**
- One `dispatch(contributor, errorLabel, intent)` replaces the 6 dispatchers;
  a single `@Suppress("UNCHECKED_CAST")` at the framework seam — `processIntent`'s
  `when` guarantees the contributor/intent pairing.
- One generic `bind<S>(contributor, slot)` replaces the 7 observe blocks.
- Error-log labels are now per-section (`"Update notifications failed"`) instead
  of per-field (`"Update vibration failed"`) — log-only coarsening; user-visible
  error messages come from `e.message` and are unchanged.
- `SettingsViewModelTest` (9 tests, all sections) passes unchanged.

## PR 2.4b — ProjectDetailViewModel: single observer + side-effect out of combine

The planned `ProjectTasksViewModel` + `ProjectMetadataViewModel` split was
rejected: post-MR-6d the VM is cohesive (one aggregate stream; every intent
mutates either the project or its tasks through one TOCTOU-guarded mutate
path). A split would duplicate the project subscription and force a merge
layer for the single `ProjectDetailUiState`.

**Done instead:**
- **One Room observer instead of five.** The state combine re-subscribed
  `projectRepo.observe(projectId)` five times (once directly, four inside
  `flatMapLatest` guards); parentOptions re-subscribed it a sixth time. All
  streams now derive from the single collected `_projectFlow: StateFlow<Project?>`.
- **Side effect moved out of `combine`** (anti-pattern per
  `singularity-todo-vm-migration-playbook`): `draftState.seed(...)` and the
  `_latestProject` TOCTOU update now happen in the project collector, not in
  the combine transform. `ProjectDetailDraftState.seed` is idempotent
  (initialized guard), so the early `isDeleted` emission re-seeding is unchanged
  in behavior; the state transform is now pure.
- `ProjectDetailViewModelTest` passes unchanged.

## Consequences

- Both "god-VMs" are now honest coordinators; the audit's line-count smell is
  addressed by removing duplication rather than by adding indirection.
- Future feature work adds a section by declaring a contributor + one `bind`
  call + one `processIntent` branch (Settings) — or a new branch in the sealed
  intent `when` (ProjectDetail).
- If Settings grows actual cross-section coupling later, the split decision can
  be revisited with the boilerplate already gone.
