# PR-0.3 retro: KDoc fix batch + ADR supersede

## Context

PR-0.3 added KDoc to 3 files and superseded 4 dead UI-testing ADRs.

## Findings

### 🟢 Clean

- TagGroupsViewModel KDoc added + `addCloseable(scope)` fixed (canonical pattern)
- SavedAgendaViewsRepository and ChecklistRepository KDoc added
- 4 UI-testing ADRs superseded via `ui-testing-deferred.md` (supersedes chain documented)
- Date inversion in test-suite-tag-defaults (2026-09-26) vs production-readiness-findings (2026-09-25) fixed
- `VmCloseable` violation in TagGroupsViewModel fixed as part of this PR

### 🟡 ADR-worthy

1. **KDoc rule false positives with sealed interfaces.** AppVersionGateViewModel's KDoc is attached to its `sealed interface` (the first declaration in the file), not to the `class` below. The rule only checks `docComment` on the class itself. Resolution: these cases are in the baseline as suppressed findings — not a regression risk.

2. **Baseline regeneration removes entries.** Running `detektBaseline --rerun-tasks` without all rules registered (e.g., after a module-level detekt invocation) regenerates the baseline without all custom rules, inadvertently removing entries. Lesson: always regenerate baselines with the full rule set and commit the resulting baseline.

3. **DIGEST merge conflicts are likely.** Every PR that touches ADRs creates a conflict in DIGEST.md (the aggregated file). The conflict was straightforward (duplicate bullet lines). Mitigation: future ADRs should not add DIGEST bullets — DIGEST is regenerated by `refresh-decisions-digest.sh` automatically.

## Decision

1. **No fast-follow PR needed.**
2. **Baseline drift risk** → documented: always regenerate baselines via the full pipeline, not module-level invocations.
3. **DIGEST conflicts** → no action; unavoidable given the auto-generation approach.

## Consequences

- PR-0.4 (production BAN fixes) will address remaining technical debt: TODO/FIXME cleanup, stateIn removal, runBlocking fixes.
