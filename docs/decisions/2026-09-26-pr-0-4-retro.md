# PR-0.4 retro: production BAN fixes

## Context

PR-0.4 fixed two canonical-pattern violations in production code.

## Findings

### 🟢 Clean

- `AndroidPomodoroTaskListProvider`: removed `stateIn` import, replaced with `MutableStateFlow` updated by `scope.launch` — matches the canonical MviViewModel pattern
- `PlatformModule.jvm.kt`: replaced raw `runBlocking {}` with `koinBridge {}` (greppable helper that wraps `runBlocking`)
- Auto-format via `detekt --auto-correct` cleaned up trailing comma / blank line debt in 6 other files

### 🟡 ADR-worthy

1. **Detekt auto-correct modifies unrelated files.** Running `--auto-correct` to fix the 4 style violations in `AndroidPomodoroTaskListProvider` also reformatted 6 unrelated files (NoteAiController, TaskDetail, FakeAppDatabase, FakeRepositories, Calendar tests). This is normal detekt behavior but worth noting: always review the full diff of `--auto-correct` runs.

2. **`stateIn` in production — limited scope found.** Only one production use of `stateIn` was found (`AndroidPomodoroTaskListProvider`). The rule is working correctly.

3. **Remaining `runBlocking` uses are legitimate.** All other `runBlocking` calls in production are:
   - `KoinBridge.kt` — the greppable bridge helper itself (not production code calling runBlocking)
   - `FileLogWriter.kt` — I/O flush operations where blocking is appropriate
   - `SettingsDataStoreMigration.runBlocking()` — one-shot migration at startup, now using `koinBridge {}`
   - `PlatformModule.android.kt` — Android platform migrations at startup (necessary, no alternative)
   - `SettingsDataStoreMigration.kt:runBlocking()` — the migration class itself (acceptable at startup)

## Decision

1. **No fast-follow PR needed.**
2. **No further `stateIn` cleanup required** — only one instance existed and it's now fixed.

## Consequences

- The 20+ `TODO:` comments in production code remain as future work — tracked in per-feature ADRs, not blocking.
- `PlatformModule.android.kt` still has two `runBlocking` calls — these are at module initialization time (startup), not inside VMs or repositories. Acceptable for now.
