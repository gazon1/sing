## Context

During the Phase 9-10 profile migration, two deprecated convenience overloads were left in `ProfileRepositoryImpl` and `FakeProfileRepository` as a transitional layer:

- `ProfileRepositoryImpl.create(name, emoji, colorIdx): ProfileId`
- `ProfileRepositoryImpl.update(id, name, emoji, colorIdx)`
- `FakeProfileRepository.all(): Flow<List<Profile>>`
- `FakeProfileRepository.create(name, emoji, colorIdx): ProfileId`
- `FakeProfileRepository.update(id, name, emoji, colorIdx)`
- `FakeProfileRepository.getById(id): Profile?`

All production callers were migrated to the canonical `create(Profile)` / `update(Profile)` APIs. Only one test caller remained: `AccountSettingsViewModelTest.kt:23` used `FakeProfileRepository.create(name, emoji, colorIdx)`.

## Idea

Delete all six deprecated overloads and migrate the last remaining test caller to the canonical `create(Profile(...)).getOrThrow().id` form.

## Decision

1. Delete `ProfileRepositoryImpl.create(name, emoji, colorIdx)` and `update(id, name, emoji, colorIdx)`.
2. Delete `FakeProfileRepository.all()`, `create(name, emoji, colorIdx)`, `update(id, name, emoji, colorIdx)`, and `getById(id)`.
3. Migrate `AccountSettingsViewModelTest` to:
   ```kotlin
   val newId = fakeProfileRepo.create(
       Profile(
           id = ProfileId.generate(),
           name = "Alice",
           emoji = "😀",
           colorIdx = 0,
           isDefault = false,
           createdAt = Instant.fromEpochMilliseconds(0),
           updatedAt = Instant.fromEpochMilliseconds(0),
       ),
   ).getOrThrow().id
   ```

## Rationale

The canonical `create(Profile)` / `update(Profile)` API is:
- Self-documenting: all Profile fields are explicit at call sites.
- Type-safe: `ProfileId` is generated by the caller, not returned as a separate step.
- Consistent with the rest of the codebase (`NoteRepository`, `TaskRepository`, `ProjectRepository`, `TagRepository` all use entity objects).

The deprecated string-based overloads were a migration convenience that served their purpose and are now dead code.

## Consequences

- **Breaking for any future external callers** that relied on the deprecated overloads — they must migrate to `create(Profile(...))`.
- The `Profile` factory is verbose for tests; consider adding a test-specific builder or factory if the pattern repeats.
- `FakeProfileRepository` is now fully consistent with the real `ProfileRepository` interface.
