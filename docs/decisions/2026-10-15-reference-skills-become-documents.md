# A skill that describes code is a document

## Context

`AGENTS.md` listed a retired-skill policy ("do not resurrect") that was already stale
before anything was removed: four `*-RETIRED` directories sat in `.agents/skills/`, and
`singularity-todo-task-snapshot-testing` carried the description
`NOT ADOPTED — research notes only`. Five entries were consuming catalog budget to tell an
agent not to use them.

That budget is not hypothetical. Skill descriptions are loaded before any skill is chosen,
and they are shortened when they do not fit — the harness states this in its own
instructions, and `docs/SKILLS-CATALOG.md` is the maintained copy of the same list. Dead
entries there are paid for by live ones.

Underneath the tidiness problem was a classification one. Five project skills described the
current state of the code rather than a procedure:

- `singularity-todo-notifications` carried a section titled *"There is no NotificationPort
  — it was deleted"* and a *"Current Architecture (2026-09-22)"* heading.
- `singularity-todo-sync` listed `Key Files` and restated the merge strategy.
- `singularity-todo-mcp-server`, `singularity-todo-kmp-platform-specific` and
  `singularity-todo-task-snapshot-testing` did the same.

These rot for a specific reason. A skill is loaded *because* it is wanted for a task, and
its value is that it survives refactors — a procedure holds. A description of how the code
works today is invalidated by every change to that code, and nothing forces it to be
updated, because nothing detects that a `SKILL.md` describing `SyncOutbox` is out of date.
An agent reading it learns the shape of a system that no longer exists. It is not that the
agents ignored the skills; from the agent's side, reading the source was the more reliable
move.

## Idea

- **A.** Leave the split as it is; the catalog is advisory and drift is tolerable.
- **B.** Delete the five dead entries and leave the rest of the taxonomy alone.
- **C.** Draw the line by what the document *is for*, and move everything on the wrong side
  of it.
- **D.** Collapse `singularity-todo-*` into `docs/` entirely, per the tree-docs argument.

## Decision

**C**, and the criterion is:

> A skill describes an **action** an agent performs. A document describes a **state** the
> code is in. An action is worth loading on demand; a state is worth having where it can
> be found by name.

Four skills became documents:

| Was | Is now |
|---|---|
| `singularity-todo-sync` | `docs/architecture/sync.md` |
| `singularity-todo-notifications` | `docs/architecture/reminders-and-notifications.md` |
| `singularity-todo-mcp-server` | `docs/architecture/mcp-server.md` |
| `singularity-todo-kmp-platform-specific` | merged into `docs/PLATFORM-REFERENCE.md` |

The fourth is a merge rather than a move because it and `PLATFORM-REFERENCE.md` answer the
same question — what the KMP seam looks like today — and one file named after the seam is
discoverable in a way two files about the same subject are not. That is the whole argument
of the change applied to itself.

And five dead entries were deleted: `grill-me-RETIRED`, `grill-with-docs-RETIRED`,
`singularity-todo-koin-di-RETIRED`, `singularity-todo-vm-koin-scoping-RETIRED`, and
`singularity-todo-task-snapshot-testing`. The last was 169 lines of Roborazzi setup for a
tool this project does not use, verified on 2026-09-08 and superseded by
`2026-09-30-roborazzi-not-built-superseded`; the ADR is the record, the coordinates were
stale by construction. `docs/doc-maintenance.md` now holds the retired list with a reason
and an ADR per row, which is where `AGENTS.md` was keeping it in four lines.

### The generated block moved with the document

`singularity-todo-mcp-server` was one of exactly two documents whose `ADR tools` block is
generated by `scripts/render-adr-tools-section.py` and verified by the **blocking** gate
`skills describe the tools that exist`. Moving the prose without the markers would have
left the generator with nothing to write into; moving it and forgetting to repoint
`renderer.DOCUMENTS` would have been worse — the gate iterates that tuple, so dropping the
entry would keep it green while checking one document instead of two and printing
`OK — 1 skill(s)` in a line nobody reads.

So the tuple is repointed rather than shortened, and `TargetSetTest` asserts three things:
the tuple still has two entries, both files exist, and each is compared independently —
the failure it guards against being one document drifting while its sibling stays correct.

`SKILLS` is kept as an alias of `DOCUMENTS` because `check-skill-drift.py` and its tests
import that name. Renaming it would break callers to make a name accurate, which is the
wrong trade for a comment to carry.

**D was rejected.** It would have thrown away in-skill loading, description-based discovery,
and four gates that currently work, to reach an outcome the tree already provides for the
half of the corpus that was genuinely describing state.

## Rationale

The catalogue was carrying 88 project skills, and the ones an agent most needed to find —
sync architecture, reminders, the MCP server — were the ones most likely to be wrong,
because they were the ones that described code. That is backwards, and no amount of catalog
discipline fixes it: the drift mechanism is that nothing knows when a `SKILL.md` stops
matching its subject.

Splitting by role fixes it at the seam. A document in `docs/architecture/` sits next to the
code it describes, is listed by name in the orientation layer's tree, and is updated by
whoever changes the subsystem. A skill stays loaded only when it is wanted, and the
description budget it competes for goes to skills that are wanted.

## Consequences

- Project skills drop from 88 to 83; the catalogue from 127 entries to 118. Five entries
  that said "do not use this" no longer compete with live ones for description space.
- `docs/architecture/` is expanded by name in the generated tree, so the three new
  documents are discoverable without reading the catalogue.
- Nine files referenced the moved skills (7 sibling skills, `AGENTS.md`, and
  `singularity-todo-repository-architecture`); all nine were repointed. References inside
  ADR bodies were left alone — `closed_adrs_keep_their_body` makes bodies immutable after
  2026-10-11, and a historical record of which skills existed at the time is not drift.
- The retired list moved from `AGENTS.md` (4 lines, going stale) to
  `docs/doc-maintenance.md` (a table with a reason and an ADR per row). That is the same
  trade this ADR makes, applied to the policy itself.
- **Known gap:** `docs/decisions/2026-09-22-alarmmanager-reminders.md` backticks
  `.agents/skills/singularity-todo-notifications/SKILL.md`, which no longer exists.
  `check-doc-dead-refs.py` reports it as *drift*, not *dead*, because it resolves by
  basename and 118 other files are called `SKILL.md`. The gate cannot distinguish a deleted
  file from a moved one when basenames collide, and it passes. Not fixed here: tightening
  the resolution risks a wave of false positives across the corpus, and that is a separate
  decision with its own measurement.
- Migrating the prose does not make it *correct*. `sync.md` and `reminders-and-notifications.md`
  were written as skills and describe the system as it stood when they were written; the
  first change to those subsystems should re-verify them rather than assume they are current.
