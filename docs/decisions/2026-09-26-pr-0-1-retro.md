# PR-0.1 retro: detekt-baseline

## Context

PR-0.1 established detekt baseline files and enabled `warningsAsErrors` for shared + desktopApp.

## Findings

### 🟡 ADR-worthy

1. **DIGEST.md is oversized.** After merging PR-0.0 + PR-0.1, `refresh-decisions-digest.sh` reports 1628 lines (limit: 1500). The DIGEST aggregates all ADRs and grows with every PR. Two mitigation paths:
   - **Trim**: Remove verbose `Links` sections from old ADRs, collapse stale/deferred ADRs into a summary table.
   - **Split**: `docs/decisions/DIGEST.md` → `DIGEST-core.md` (active decisions only) + `DIGEST-archive.md` (superseded/deferred).
   - Decision: defer to PR-1.1 (docs-infrastructure ADRs) or PR-1.2 (CONTEXT.md).

2. **androidApp and mcp-server have no baselines.** These modules don't apply `:detekt-rules` and are report-only (`warningsAsErrors: false`). When their tech debt is cleaned (future PR), baselines should be generated:
   - `./gradlew :androidApp:detektBaseline :mcp-server:detektBaseline`
   - `config/detekt/detekt.yml` (not minimal) can then be applied to them once custom rules are relevant.

3. **mcp-server had redundant `detektPlugins(libs.detekt.formatting)`**, removed in this PR. The ktlint plugin was applied but the `detekt.yml` it inherited had no ktlint configuration, making it a no-op. Good catch.

### 🟢 Clean

- `shared` and `desktopApp` baselines captured correctly (930 + 1 findings respectively).
- `warningsAsErrors: true` in shared/desktopApp — new violations will now fail CI.
- All modules pass `detekt` with 0 new findings after baseline.

## Decision

1. **No fast-follow PR needed** — no critical bugs or blockers found.
2. **DIGEST oversized** → tracked in PR-1.1 or PR-1.2 backlog.
3. **androidApp/mcp-server baselines** → future cleanup PR (not in current epic scope).

## Consequences

- `just docs-audit` should be run before every PR to catch DIGEST drift early.
