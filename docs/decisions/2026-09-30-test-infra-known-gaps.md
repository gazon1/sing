# Test-infra ratchet: оставшиеся долги после MR-5

## Context

MR-0…MR-5 (ветка `refactor/test-infra-ratchet`) закрыли диагностику, послойные
assertions, паритет платформенного модуля, контракты Fake⇄Room и двусторонний
контракт TestTags. Ретро-случай был продуктивен: три из четырёх новых проверок
сначала оказались «зелёными» не потому, что мир корректен, а потому что сами
проверки ничего не делали.

Этот ADR фиксирует четыре оставшихся наблюдения. Два из них уже исправлены
критическим коммитом, два — предмет будущей работы. Здесь важно не столько
список, сколько формулировка корневых причин: почти все находки одного класса.

### 1. Тестовая логика в production source set (исправлено)

`TestTagsCatalog` был написан в `commonMain` и читал файлы через
`java.nio.file.Files`. Класс использовался **только** из `jvmTest`. Последствия:

- `commonMain` перестаёт быть multiplatform-чистым: `java.nio.file` доступен
  только на JVM/Android, и на Android требует API 26.
- Тестовая логика попадает в production-бинарь приложения.
- Ничто не мешало этому пройти: правило `commonMain does not import java io
  File` проверяло ровно один класс — `java.io.File`.

### 2. Проверки, которые проходят, ничего не проверяя (класс F, повторно)

Три независимых случая за одну ветку:

| Проверка | Почему была зелёной |
|---|---|
| reverse-wiring тест тегов | Резолвила source roots от working dir тестового JVM (каталог модуля) → сканировала 0 файлов |
| golden-таблица `TAGS.md` | Классификатор молча отбрасывал нераспознанные константы → расхождение не виделось |
| `TestTagsWiringTest` | Сопоставлял имена подстрокой: `SyncEventType.RESTORED` «применял» `EditorOverflow.RESTORE` |

Общий корень: проверка, которая при неудаче возвращает «пусто», неотличима от
проверки, которая прошла. Ни одна из трёх не имела positive control.

### 3. `Clock.System` в тестах: молчащее подавление (частично исправлено)

**Первая версия этого пункта была фактически неверной.** Она утверждала, что
правило `NoDirectClockSystem` не покрывает test source set. Проверка
показывает обратное:

- `:shared:detekt` включает `src/jvmTest/kotlin` в `source.setFrom`;
- пробный файл с `Clock.System` в `jvmTest` правило ловит;
- правило активно в `detekt.yml`, в baseline ноль его записей.

Долг не «unenforced» — он **признан и заглушен**: 51 тестовый файл начинается с

```kotlin
@file:Suppress("NoDirectClockSystem")
```

**без единого слова причины.** Это ровно тот же класс дефекта, что и в пункте 2
(«правило прошло, но не сработало»), только в форме подавления: file-level
suppress глушит правило на весь файл, включая будущие инъекции, которые
действительно опасны. Проверить это оказалось нетривиально — файл с
добавленной строкой `Clock.System` оставался зелёным, пока не выяснилось,
почему; без positive control на это ушло несколько итераций.

Реальная опасность — не `createdAt = Clock.System.now()` в фикстурах (он
безвреден), а инъекция `Clock.System` в VM под тестом: статистика считает
«сегодня» и «последние 7 дней», agenda решает по дате, репозитории фильтруют
по `today`. Именно такие места и надо чинить.

### 5. Пакет диагностики MR-1 был сломан в двух местах (исправлено)

Находка из диагностики настоящего флейка: `ProjectsFlowTest.opening_a_project_
reaches_its_detail_screen` падает примерно в одном прогоне из двух (проверено:
зелёный прогон → красный прогон на неизменённом коде). Вместо того чтобы гадать,
были прочитаны артефакты, которые MR-1 и положил создавать для такой ситуации —
и они оказались непригодны:

1. **Каталог не идентифицировал тест.** `currentTestClassSimpleName()` брал
   первый фрейм стектрейса, в имени которого встречается `Test`. Между телом
   теста и раннером лежат два таких фрейма: синтетический `SkikoComposeUiTest$runTest$1$1$…`
   и `kotlinx.coroutines.test.TestDispatcher`. В итоге **все** падения сьюта
   попадали в один и тот же каталог, а при параллельном исполнении ещё и
   затирали друг друга. Теперь предикат инвертирован: берётся первый фрейм,
   принадлежащий собственному тестовому коду проекта.
2. **`db-state.txt` никогда ничего не содержал.** `testPlatformModule()` биндит
   базу как `single<AppDatabase> { FakeAppDatabase() }` — по интерфейсу, а пакет
   резолвил `getOrNull<FakeAppDatabase>()`, по конкретному типу. Результат —
   всегда null и заглушка `<FakeAppDatabase not registered…>`. То есть один из
   трёх артефактов, которые MR-1 действительно поставляет, не работал ни разу.

Оба исправлены и проверены принудительным падением: пакет теперь ложится в
`build/diagnostics/<ИмяТеста>/attempt-1/`, а `db-state.txt` печатает дамп.

Отдельно: `tree-merged.txt` / `tree-unmerged.txt` в MR-1 не пишутся — это
осознанное сокращение объёма, задокументированное в `FailureBundle` и включаемое
флагом `-Dsingularity.ui.dumpTree=true`. Дефектом это не считаю; в отчёт попало
потому, что ожидалось по плану.

### 4. Два парсера `TestTags.kt` (не исправлено)

`TestTagsCatalog` (полный разбор с учётом вложенных `object`) и
`TestTagsWiringTest` (отдельный regex `const val ([A-Z][A-Z0-9_]*)`). Расходятся
в понимании вложенности: wiring-тест видит `ARCHIVE`, каталог — `Dialog.CONFIRM`
как `Dialog.CONFIRM`. Расхождение безобидное, но при добавлении константы два
механизма дадут два разных ответа.

Дополнительно: `TagsMd.dynamicMeta` хранит «Used for» и пример входа вручную.
Новая динамическая функция требует правки **двух** файлов (`TestTags.kt` и
`TagsMd.kt`). Тест падает с указанием, что добавить, но механизма «одного места
правки» нет.

## Decision

**Исправлено сейчас, отдельным коммитом:**

1. `TestTagsCatalog` и `TagsMd` перенесены в `jvmTest` (тот же пакет, правки
   импортов не потребовались).
2. Правило `commonMain does not import java io File` расширено до
   `commonMain does not use JVM file APIs`: покрывает `java.nio.file.*` и
   `kotlin.io.path.*` плюс конкретные файловые классы `java.io`. `AdrTools`
   (MCP `write_adr`) внесён в allowlist с обоснованием — это осознанное
   проникновение, а не oversight.
3. `AGENTS.md`: `:desktopApp:jvmTest` → `:desktopApp:test` (2 места). Задачи
   `jvmTest` в `:desktopApp` не существует; агент по инструкции получает
   «Cannot locate tasks».
4. `TestTagsWiringTest`: сопоставление по границе идентификатора вместо подстроки;
   `EditorOverflow.RESTORE` добавлен в `knownUnapplied` с причиной.
5. Четыре самых опасных теста переведены с реальных часов на управляемые, и
   blanket-suppress с них снят целиком (51 → 47 файлов):
   - `StatisticsViewModelTest` — считает «сегодня» и «последние 7 дней»;
   - `ProjectDetailViewModelTest` — рендерит даты напоминаний;
   - `SavedAgendaViewModelTest` — `SavedAgendaDeps.clock`;
   - `SlotTestFixtures` (commonTest) — слоты резолвят due-даты.

   Инструмент уже существовал: `FakeClock` в `test/fakes/FakeClock.kt`
   (`setNow` / `advance`). Константа инстанта вынесена на уровень файла с
   комментарием, почему фиксированная дата, а не «сегодня».
6. Пакет диагностики MR-1: имя каталога и резолв базы (пункт 5 Context).
   Проверено принудительным падением — артефакты пишутся и называются верно.

**Отложено, с явным триггером:**

7. Оставшиеся 47 подавлений. Форма работы — по одному файлу за MR, начиная с
   тех, где `Clock.System` попадает в VM под тестом. Для каждого оставленного
   подавления нужна причина; сегодня их нет ни у одного, и это делает
   молчаливое подавление неотличимым от забытой проверки.
8. Слияние двух парсеров в один. `TestTagsWiringTest` должен использовать
   `TestTagsCatalog.staticTags()`; после слияния правило «каждая константа
   применена» и golden-таблица читают один источник истины.
9. «Used for»/пример для динамических функций — либо оставить как есть с
   явным указанием в скилле, что правка в двух файлах это ожидаемо, либо
   вынести в KDoc самого `TestTags.kt` и парсить оттуда.
10. Сам флейк `ProjectsFlowTest.opening_a_project_reaches_its_detail_screen`
    (≈1 прогон из 2 на неизменённом коде). Диагностический пакет теперь
    пригоден, так что причина находится существенно дешевле, чем до этого
    коммита; разбирать имеет смысл именно с ним, а не наугад.

## Rationale

Пункты 1–5 — дёшево, безопасно и убирают ловушки, на которые агент наступает
повторно. Пункт 6 большой и поэтому отложен: 47 файлов одним MR не ревьюится.
Пункт 7 — устранение дублирования, но не блокер.

Пять пунктов из шести первоначальных наблюдений оказались одним и тем же
дефектом в разных обёртках: **механизм, который тихо ничего не делает**. Скан
сканировал ноль файлов; классификатор отбрасывал нераспознанное; сопоставление
шло по подстроке; подавление глушило правило на весь файл. Ни один из них не
пал без positive control, и в случае с `Clock.System` обнаружение заняло
несколько итераций — сначала показалось, что правило не покрывает тесты.

Главное, что фиксирует ADR: **проверка, которая может молча ничего не сделать,
хуже отсутствующей проверки** — она создаёт ложную уверенность и тратит время
на ложные загадки. Каждая новая проверка в этом проекте обязана иметь
positive control, зафиксированный в описании MR, и защитный тест, если она
сканирует файловую систему (как `reverse wiring check actually scans production
sources` рядом с самим reverse-тестом). По той же причине blanket-suppress без
причины приравнивается к отсутствию правила.

## Consequences

- `commonMain` снова multiplatform-чистый; Konsist-правило это стережёт.
- Агент, читающий `AGENTS.md`, не получает несуществующую задачу Gradle.
- Классификатор `TagsMd` и wiring-тест по-прежнему расходятся; это не авария,
  но при добавлении вложенной константы возможна путаница — устранено в MR, где
  дойдёт до пункта 7.
- Долг по `Clock.System` уменьшен (51 → 47 подавлений) и дальше сам не уменьшается.
  Пока reasons не проставлены, blanket-suppress остаётся неотличимым от
  забытой проверки: к каждой новой VM-тесте с `clock` относиться как к
  потенциально date-dependent, пока не переведена на `FakeClock`.
