# Contract: The Maestro Flow `tasks-logbook-note`

**Feature**: [spec.md](../spec.md) · **Scenario**: `TASK-LOG-01`
**Date**: 2026-10-25

---

## Что флоу доказывает

Один пользовательский путь целиком: **заметка, написанная из логбука задачи, остаётся в этом
логбуке**. Это единственный путь, который был сломан, и единственный, который проходит через
навигацию между графами (задача → заметки → обратно в задачу), поэтому desktop-тест его не
заменяет.

Флоу проверяет три утверждения спеки:

| Утверждение | Как |
|---|---|
| FR-002 — до сохранения заметки нет | `assertVisible: logbook_empty` сразу после открытия логбука |
| FR-001/FR-003 — заметка создаётся с привязкой и остаётся | `extendedWaitUntil: logbook_note_by_title_…` после возврата в задачу |
| FR-004 — в логбуке только заметки этой задачи | флоу работает на одной задаче; чужие заметки — в юнит-тесте T1 |

## Адресация элементов

| Элемент | Как адресуется | Почему |
|---|---|---|
| карточка логбука | `id: logbook_section` | контроль/контейнер — по id (конвенция Maestro) |
| пустое состояние | `id: logbook_empty` | по id |
| кнопка «+» | `id: logbook_add_note_button` | контрол — по id, не по `contentDescription` |
| строка заметки | `id: logbook_note_by_title_${RUN_ID}_…` | динамический тег по заголовку: id заметки — ULID, его флоу не знает |
| заголовок заметки | `id: note_editor_title_input` | поле ввода; `TextFieldState`, не controlled — `inputText` работает |
| сохранение | `id: note_editor_save` | явное сохранение вместо надежды на тайминг автосейва |
| строка задачи | `id: task_item_buy_milk` | штатная фикстура `helpers/seed-task.yaml` |

## Что считается провалом

- заметка не появилась в логбуке после сохранения;
- в логбуке появилась пустая «(untitled)»-строка до того, как что-то было написано;
- флоу не дошёл до конца (логин, навигация, скролл) — тоже провал: сценарий не выполнен.

## Требования к окружению

- Устройство: подключённый Android (в прогоне — realme RMX3938, Android 15, 720×1600).
- APK установлен **из этого же дерева** (`./gw :androidApp:installDebug
  -Pandroid.device=<serial>`): флоу против старой сборки проверяет не то.
- Данные приложения очищены перед прогоном (deep link `todo-debug://seed?reset=content`),
  иначе в логбуке могут быть чужие заметки.

## Артефакты прогона

- Скриншот `tasks/logbook-note` — состояние логбука с только что созданной заметкой.
- Лог прогона — в `build/diagnostics/<что>-<метка>.log`; ожидание одним
  `./wait-for <лог> <паттерн>`.
- Результат прогона попадает в матрицу покрытия (`just trace-results --maestro`).
