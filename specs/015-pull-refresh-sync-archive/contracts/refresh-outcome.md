# Контракт: результат обновления и сообщение пользователю

**Feature**: `specs/015-pull-refresh-sync-archive`
**Дата**: 2026-10-25

Контракт описывает словарь исходов обновления и то, что пользователь видит для
каждого из них. Место одно: разбор исхода в сообщение живёт в общем коде, а не в
каждом экране, поэтому все экраны говорят об одном и том же одинаково.

---

## Исходы

| Исход | Условие |
|---|---|
| Архивирование удалось | Шаг переноса завершён; в `archived` — число перенесённых задач |
| Архивирование не удалось | Шаг переноса завершился ошибкой; в `archived` — ошибка |
| Синхронизация прошла | Цикл выполнился; обе фазы (отправка и загрузка) успешны |
| Синхронизация не удалась | Цикл не начался или одна из фаз упала; в `sync` — причина |
| Синхронизации не было | Активной области синхронизации нет — пользователь не вошёл в аккаунт |

Два последних шага независимы: неудача одного не отменяет другой. Перенос
завершённых задач в архив — локальная операция, и она выполняется всегда, когда
пользователь её запросил.

---

## Сообщения

| Ситуация | Что видит пользователь |
|---|---|
| Перенесено N > 0, синхронизация прошла | «Синхронизировано. N задач перенесено в архив» |
| Перенесено 0, синхронизация прошла | «Синхронизировано. Переносить было нечего» |
| Перенесено N > 0, синхронизация не удалась | «N задач перенесено в архив на устройстве. Синхронизация не удалась: <причина>» |
| Перенесено 0, синхронизация не удалась | «Переносить было нечего на устройстве. Синхронизация не удалась: <причина>» |
| Перенесено N, синхронизации не было (нет входа) | «N задач перенесено в архив. Синхронизация недоступна без входа в аккаунт» |
| Архивирование не удалось | «Не удалось перенести завершённые в архив: <причина>» |
| Архивирование не удалось и синхронизация не удалась | «Не удалось перенести завершённые в архив: <причина>. Синхронизация не удалась: <причина>» |

Последняя строка — следствие независимости шагов: обе могут упасть, и одно
сообщение говорит об обоих, потому что это одно действие с двумя шагами.

---

## Правила оформления

| Правило | Почему |
|---|---|
| Число — фактически перенесённое этим запуском | «N задач» про общее число завершённых вводит в заблуждение |
| Причина — словами пользователя, без технических кодов | Причина синхронизации может быть технической; пользователю нужен смысл |
| Архивирование и синхронизация упоминаются в одном сообщении | Это одно действие с двумя шагами, а не два события |
| Ноль — это успех, а не ошибка | «Переносить было нечего» — обычное состояние, а не сбой |
| Сообщение короткое и исчезает само | Оно подтверждает действие, а не требует ответа |
| Сообщение о неудаче говорит, что перенос на устройстве уже выполнен | Пользователь должен знать, что работа в безопасности: отвалился только сервер |

---

## Что контракт не задаёт

- **Где** показывается сообщение. Оно принадлежит экрану, который запросил
  обновление; остальные экраны молчат.
- **Сколько живёт сообщение** — это решает общий компонент уведомлений.
- **Вид индикатора** — это решает общий контейнер.
