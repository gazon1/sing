### 2. Новые контракты (5 interfaces) + удаление runBlocking

| Файл | Было | Стало |
|---|---|---|
| `feature/notes/NotesRepository.kt` | `class NotesRepository` | `interface NotesRepository` + `RoomNotesRepository` impl |
| `feature/projects/ProjectsRepository.kt` | `class` | `interface` + `ProjectsRepositoryImpl` impl |
| `feature/tags/TagsRepository.kt` | `class` | `interface` + `TagsRepositoryImpl` impl |
| `core/auth/SessionStore.kt` | `class` с `accessTokenBlocking()`, `refreshTokenBlocking()`, `deviceIdBlocking()` | `interface SessionStore` (только `Flow`/suspend) + `DataStoreSessionStore` impl |
| `core/settings/SettingsRepository.kt` | `open class` с `aiApiKeyBlocking()`, `aiModelBlocking()`, `userIdBlocking()` | `interface` (только `Flow`/suspend) + `DataStoreSettingsRepository` impl |

Все `*Blocking()` методы удалены. Использования `userIdBlocking()` (4 VM + SearchScreen) мигрируют:
- `NotesViewModel`, `TasksViewModel`, `ProjectsViewModel`, `TagsViewModel`: `init` блоки получают `userId` через `runBlocking { settings.userId.first() }` внутри самого VM (это допустимо в `init` для seed initial state) — либо через новый `@Provides @Named("userIdSync") fun userIdSync(settings: SettingsRepository): String = runBlocking { settings.userId.first() }` binding, который выдаёт snapshot.
- `SearchScreen`: `val results by searchUseCase(query, settingsRepo.userIdBlocking())` → `val results by remember { searchUseCase(query, runBlocking { settingsRepo.userId.first() }) }` либо передать `UserId` параметром в VM.
