# Write Pipeline — Three Canonical Primitives

Room `@Upsert` is a full-row REPLACE: any column not explicitly set takes its Kotlin default.
This makes three distinct operations necessary.

## The Three Primitives

### 1. `create` — INSERT with caller-supplied entity

```
guard → upsert(callerEntity) → sync.enqueue
```

The caller provides the complete entity. Used for brand-new objects (ID generated by caller or IdGenerator).

```kotlin
// create: caller owns all field values
override suspend fun create(item: Task): Result<Task> = runCatching {
    currentUser.assertCanWrite(entityId = item.syncId, entityUserId = item.userId)
    val toInsert = item.copy(userId = currentUser.scopedUserId.value)
    taskDao.upsert(toInsert.toEntity())
    syncRepository.enqueue(toInsert)
    toInsert
}
```

### 2. `edit` — read-modify-write (user edits existing entity)

```
guard → read existing from DB → validate → upsert(modified) → sync.enqueue
```

The caller proposes a transformation of an existing entity. The repository **must read first**
to avoid destroying fields it doesn't manage (e.g. server-owned sync metadata, join-table data).

```kotlin
// edit: read existing, then modify
override suspend fun update(item: Task): Result<Task> = runCatching {
    currentUser.assertCanWrite(entityId = item.syncId, entityUserId = item.userId)
    // Read-before-write guard: reject updates to non-existent entities.
    taskDao.getByIdForUser(item.id.value, currentUser.scopedUserId.value.value)
        ?: throw IllegalArgumentException("Task not found: ${item.id.value}")
    val toUpdate = item.copy(userId = currentUser.scopedUserId.value)
    taskDao.upsert(toUpdate.toEntity())
    syncRepository.enqueue(toUpdate)
    toUpdate
}
```

**Why the read guard?** Without it, `dao.upsert(item.toEntity())` does a full-row REPLACE.
Any entity field not set by the caller — `createdAt`, `serverVersion`, `hlc`, join-table
data — reverts to its Kotlin default. The read confirms the row exists before destroying it.

**Why not always use read-modify-write for create?** Because `create` generates a new ID
via `IdGenerator` before the insert; reading a non-existent row would always throw.

### 3. `apply` — remote upsert (server-pushed entity)

```
validate server signature → upsert(serverEntity) → (no sync.enqueue)
```

Used exclusively by the sync engine for server-pushed changes. The sync engine has already
validated the server signature; no local guard or re-enqueue needed.

```kotlin
// apply: sync engine path — no guard, no re-enqueue
override suspend fun applyRemote(serverNote: Note): Result<Unit> = runCatching {
    noteDao.upsert(serverNote.toEntity())
    // no syncRepository.enqueue — already on server
}
```

## When Each Primitive is Used

| Operation | Primitive | Example |
|---|---|---|
| User creates new object | `create` | `NoteEditor` saves new note |
| User edits existing object | `edit` | `update(note.copy(title = ...))` |
| Restore from trash | `create` (with deleted fields cleared) | `NoteRepository.restore` |
| Sync engine receives server push | `apply` | `SyncRepository.processUpsert` |
| Backup restore | `create` (from backup DTO) | `BackupRepository.importPayload` |

## Domain-specific Side Effects

Outgoing links, counter updates, cross-refs — any write that is **not** the primary entity —
go **between the upsert and sync.enqueue**:

```kotlin
taskDao.upsert(toUpdate.toEntity())
saveOutgoingLinks(toUpdate.id, toUpdate.description)  // side effect
syncRepository.enqueue(toUpdate)                      // after side effect
```

## The Guard — `assertCanWrite`

**File:** `core/repository/UserScopedWriteExt.kt`

```kotlin
fun ProfileAwareCurrentUser.assertCanWrite(
    entityId: String,
    entityUserId: UserId,
)
```

Throws `CrossUserWriteException` when `entityUserId` is neither the current scoped user nor `UserId.anonymous`.

## When `assertCanWrite` is NOT needed

| Case | Why |
|---|---|
| `create` generates entity internally (e.g., `TagGroupRepositoryImpl`) | No external input; `userId` is stamped from `scopedUserId` |
| Sync bootstrap / pull handler calls `dao.upsert()` directly | Already validated by upstream sync protocol |
| `apply` (remote upsert) | Server signature already validated |
| `delete`, `archive`, `unarchive`, `restore` | DAO `*ForUser` filter (`WHERE user_id = :scopedUserId`) already prevents cross-user writes; `require(rows > 0)` throws if entity not found or not owned. No external `userId` to validate — the operation is scoped to the current user by construction. |

**Note on error semantics:** These methods throw `IllegalArgumentException` ("not found") rather than `CrossUserWriteException` (authorization). Both prevent the write, just with different error types. If you prefer `CrossUserWriteException` semantics, add a read-first `assertCanWrite` call — but it costs an extra DB read per operation.

## Guard vs DAO-level filter

Two layers of protection:

1. **`assertCanWrite`** — authorization check. Throws `CrossUserWriteException` if the entity's `userId` doesn't match the current profile.
2. **DAO `*ForUser` methods** — data isolation. SQL `WHERE user_id = :userId` prevents leaking data across users even if the guard is bypassed.

Both are required. The guard is the first line of defense and provides a clear error. The DAO filter is defense-in-depth.

## `userId` type matters

| Entity | `userId` type | Guard call |
|---|---|---|
| `Task`, `Project`, `Note`, `Reminder` | `UserId` | `assertCanWrite(id, item.userId)` |
| `Tag` | `String` | `assertCanWrite(id, UserId(item.userId))` ← wrap |
| `TagGroup` | `String` | `assertCanWrite(id, UserId(existing.userId))` ← wrap |
| `SavedAgendaView` | `String` | `assertCanWrite(id, UserId(uid.value))` after normalisation |

**ADR:** `docs/decisions/2026-09-25-repository-architecture-gaps.md` — `Tag` and `TagGroup` should migrate to `UserId`.

## Testing `assertCanWrite`

```kotlin
// shared/src/commonTest/kotlin/com/singularity/todo/core/repository/UserScopedWriteExtTest.kt
class UserScopedWriteExtTest {
    @Test
    fun matchesCurrentUser_doesNotThrow() {
        val cu = FakeProfileAwareCurrentUser(initialUserId = UserId("u-1"))
        cu.assertCanWrite(entityId = "task-1", entityUserId = UserId("u-1"))
    }

    @Test
    fun anonymousUser_isAccepted() {
        val cu = FakeProfileAwareCurrentUser(initialUserId = UserId("u-1"))
        cu.assertCanWrite(entityId = "task-1", entityUserId = UserId.anonymous)
    }

    @Test
    fun differentUser_throws() {
        val cu = FakeProfileAwareCurrentUser(initialUserId = UserId("u-1"))
        assertFailsWith<CrossUserWriteException> {
            cu.assertCanWrite(entityId = "task-1", entityUserId = UserId("u-2"))
        }
    }
}
```

## Audit Checklist

Before merging any PR that touches repository `create`/`update`/`restore`:

**For `create`:**
- [ ] `assertCanWrite` is the **first line** before any `dao.upsert`
- [ ] `syncRepository.enqueue(item)` is called **after** `dao.upsert`
- [ ] `item.copy(userId = currentUser.scopedUserId.value)` stamps user **after** guard

**For `edit` (user update):**
- [ ] `assertCanWrite` is the **first line**
- [ ] `dao.getByIdForUser(...)?: throw IllegalArgumentException(...)` read-before-write guard
- [ ] `syncRepository.enqueue(item)` is called **after** `dao.upsert`

**For `apply` (sync engine):**
- [ ] No `assertCanWrite` — server signature is already validated
- [ ] No `syncRepository.enqueue` — already on server
- [ ] Server entity is upserted as-is (full-row replace is correct for server data)

**Common:**
- [ ] No `require()` or manual `if (userId != ...)` — use `assertCanWrite`
- [ ] `assertCanWrite` throws `CrossUserWriteException`, not `IllegalArgumentException`
- [ ] `userId` type mismatch handled — wrap `String`-typed `userId` with `UserId()` at call site
- [ ] Domain side effects (outgoing links, counters) go **between** upsert and enqueue
